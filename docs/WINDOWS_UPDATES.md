# Windows 更新与旧 MSI 迁移

Windows 新安装包使用 NSIS EXE，安装到原登录用户的本地应用目录。后续更新直接覆盖该用户的程序文件，不再每次执行 MSI major upgrade。旧 MSI 的第一次迁移仍需要 Windows Installer 和一次管理员授权，不能承诺该次系统事务即时完成。

## 更新交接

- 插件 `check` 返回的 `Update` 资源仍负责下载与签名验证。自定义 `install_app_update` 只接受本 WebView 的资源 ID，不能指定任意安装路径或未验签字节。
- 下载使用独立的 10 分钟总超时，不再继承版本检查的 15 秒超时。前端显示下载、验签、准备退出、启动安装、已交给安装器；30 秒无进展提供提示，但不并发重试或强杀安装器。
- Windows 先把已验签 EXE 写入本次私有临时目录，再恢复接管配置和停止本地监听。准备失败不启动安装；启动失败恢复保存的路由，恢复失败保留偏好并如实提示。
- 启动安装器使用原生 `Command` 参数，随后通过正常 Tauri 退出事件释放窗口、托盘和单实例锁。安装器通过 `/CODEXXPID` 句柄等待旧进程退出；30 秒未退出则停止本次安装，不杀进程、不复制新文件。
- “已交给安装器”只表示成功启动，不等于更新已完成。后续 IPC 断开不能触发第二个安装进程。
- macOS/Linux 继续使用插件原有安装逻辑，安装成功后才进入等待重启状态。

## 兼容已发布的 MSI

自定义模板基于 Tauri CLI 2.11.4。旧安装只按本项目固定 UpgradeCode `{1482A8E8-9217-517B-8528-93A6C90E0C2F}` 和 Windows Installer machine context 检查，不执行注册表中的任意卸载命令。

只提升系统 `msiexec.exe /x {ProductCode}` 子进程的权限；EXE 安装器始终留在原登录用户下，避免使用另一个管理员凭据授权后安装到管理员的个人目录。旧 MSI 保留的 Program Files 路径不作为新安装目录。

卸载未成功、取消授权、其他安装事务占用或结果未知时，停止复制新版本。移除返回 `0` 或 `3010` 后，再次验证旧产品注册已消失，并确认新目录与卸载前记录的旧目录隔离，才写入新安装。`3010` 表示旧文件可能需要 Windows 后续清理；在上述条件成立时继续安装，不要求用户重启电脑。

旧目录通过目录句柄解析到真实路径，处理 junction、短路径和驱动别名；目标不能是旧目录或其子目录。旧路径记录保留到异常退出后的重试，防止卸载记录消失后误选旧目录。不会用整机“待重启”状态阻止更新，也不查询启动时间。配置、账号、会话目录不属于迁移删除范围。

安装器按阶段记录日志，旧版卸载另外记录 MSI 详细日志。长时间等待会持续显示已等待时间和日志位置，不强制结束系统安装事务。

## 发布入口

更新清单的 `windows-x86_64`、`windows-x86_64-nsis`、`windows-x86_64-msi` 三个键必须指向同一个 EXE 和签名。旧 MSI 客户端下载后按实际文件内容识别安装器，因此可以完成过渡。发布校验禁止混入不同的 MSI 安装目标。

官网本地下载选择器已支持优先 EXE、回退旧 MSI；官网是独立部署，软件正式发布前须同步该兼容修改。便携版仍使用手动更新。

## 验证

- 本机 Rust 回归覆盖安装交接、失败恢复、端口冲突、签名失败阶段、并发更新保护和安装包暂存；前端覆盖各阶段、迟到事件、断连和长等待。
- NSIS 模板可在本机编译，但不能据此宣称已通过 Windows 安装测试。
- `Windows installer verification` 工作流在独立 Windows runner 构建测试安装器，运行后端测试和 `scripts/windows-install-smoke.ps1`。测试包括全新安装、真实 v0.3.20 MSI 迁移、后续更新、唯一卸载项和用户配置哨兵保留；不发布正式版本。
- 正式 Release 同样要求这组原生安装测试通过才发布。普通用户的管理员授权、第三方安全软件和系统安装服务仍应在实际 Windows 环境验证；无法保证所有系统环境均无等待。
